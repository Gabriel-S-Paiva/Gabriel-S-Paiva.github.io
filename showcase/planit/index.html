A client-only travel planner with a gamification layer built to bring users back. I built the data layer and designed the gamification system.

What it is

PlanIt is a travel planner for flights, hotels and activities, built for ESMAD in 2024/25 and named ESMAD Best Project that year. It has no backend: the app follows an MV architecture and persists everything to LocalStorage, so the interesting work is in the data model and in the design.

What I did

  • Model layer. The core data logic, the seeded datasets (airports, hotels, activities, flights) and ModelHelpers.js.
  • Gamification design. A system built on the HEXAD player-type framework and Werbach’s 6D methodology, backed by five researched personas.
  • UX research and design deliverables. The competitor moodboard, wireframes and the brand identity (logo and color system).

Designing for five kinds of traveller

The gamification started with people, not mechanics. There are five personas, each profiled with the HEXAD player types, so the rewards could be checked against who would actually use them.

Averaged across all five, Free Spirit (21%) and Philanthropist (20.4%) lead and Disruptor is lowest (9.2%).

RewardIt

The gamification layer is RewardIt, a points and levels system tied to bookings. Five levels, from Explorador to Embaixador, unlock benefits as points accumulate. Points come from spending (one point per euro on individual bookings, more on travel packages), with bonuses for booking lodging, transport and insurance together, and for inviting friends.

Augmented reality

The poster and one page of the site also work as AR targets. It runs in the browser, with no app to install, and there are three experiences to try. Each has its own QR code: scan it with a phone, allow camera access, then point the camera at the image shown with it.

From wireframe to brand

The wireframes fixed the structure first: a search form on top, a grid of trip cards below, and the same layout down to mobile. Visual design came after.

I also worked on the brand identity: the logo and the color system the prototype uses.

The data layer

With no backend, the Model layer is the whole data story. Multi-destination search shows it best: given a list of cities, getTripsMulti collects the flights for each leg, builds every possible itinerary and keeps only the ones where each flight departs after the previous one lands.

The itinerary builder is a small recursive function that takes one list of flights per leg and returns every combination (a cartesian product).

The number of combinations grows quickly with the number of legs. That is fine for a seeded dataset in the browser, but it is the first thing I would change with real flight data.
